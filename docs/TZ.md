# ТЗ: Virtual Wardrobe (MVP)
Oct 27, 2026 · @Someone

## 1. Загальні відомості
Virtual Wardrobe — веб-застосунок, у якому користувач збирає цифровий гардероб зі своїх речей і складає з них образи. MVP закриває три задачі: зберігання речей, ручне складання аутфітів і автоматичні підказки з наявного одягу.

**Проблема.** Люди мають багато одягу, але не бачать усіх своїх речей разом і не пам'ятають, що з чим поєднується. Вибір образу щодня забирає час, а частина речей лишається незадіяною.

| Параметр | Значення |
| :--- | :--- |
| **Назва проєкту** | Virtual Wardrobe |
| **Тип продукту** | Веб-сайт (SPA) + REST API, mobile-first; мобільний застосунок — наступний крок на тому самому API |
| **Мета MVP** | Перевірити, що користувачам зручно вести цифрову шафу, складати образи й що прості рекомендації дають корисні комбінації |
| **Цільова аудиторія** | Спершу двоє авторів, які роблять проєкт для себе; архітектура не заважає пізніше відкрити його для інших |
| **Мова інтерфейсу** | Українська; код готується до локалізації (англійська — пізніше) |
| **Платформи MVP** | Сучасні браузери (Chrome, Safari, Firefox, Edge), мобільні та десктопні екрани; запуск локально через Docker Compose |
| **Поза обсягом MVP** | Усе з розділу 9 (фото людини, AI-примірка, погода тощо) |

### Глосарій
| Термін | Значення |
| :--- | :--- |
| **Річ (Item)** | Один предмет одягу, взуття чи аксесуар у шафі користувача |
| **Шафа (Wardrobe)** | Усі речі одного користувача |
| **Образ / аутфіт (Outfit)** | Збережена комбінація речей з назвою |
| **Рекомендація** | Згенерований системою образ, який ще не збережений користувачем |
| **Слот** | Позиція в образі: верх, низ, взуття, аксесуар, верхній одяг, сукня |

### Критерії успіху
Проєкт робиться для себе, тому успіх вимірюється власним користуванням, а не метриками аудиторії.
1. Додавання речі займає менше хвилини.
2. Обидва автори перенесли в застосунок реальну шафу (щонайменше 30 речей кожен) і справді користуються конструктором.
3. Щонайменше кожна третя рекомендація дає образ, який хочеться зберегти.
4. Сайт зручний на телефоні через браузер.

## 2. Ролі та ключові сценарії
У MVP є лише дві ролі: гість і авторизований користувач, який бачить виключно власні дані.

| Роль | Що може |
| :--- | :--- |
| **Гість** | Зареєструватися, увійти (email чи Google), відновити сесію. Інших даних не бачить |
| **Користувач** | Керувати профілем, шафою, образами, обраним; отримувати рекомендації. Доступ тільки до власних записів |
| **Адміністратор** | Не входить до MVP. Поле role закладається в БД одразу, щоб додати адмін-панель без міграції даних |

### Ключові сценарії
1. **Перший запуск.** Користувач реєструється через email або Google, потрапляє в порожню шафу з підказкою «Додайте першу річ» і за кілька кроків додає її.
2. **Наповнення шафи.** Користувач завантажує фото речі, вводить назву, обирає категорію й колір, зберігає. Річ одразу з'являється в сітці.
3. **Пошук речі.** Користувач фільтрує шафу за категорією та кольором і знаходить потрібну річ.
4. **Складання образу.** Користувач обирає речі зі своєї шафи по слотах, бачить попередній перегляд, дає образу назву («На навчання») і зберігає.
5. **Рекомендації.** Користувач відкриває розділ рекомендацій, бачить кілька готових комбінацій, зберігає потрібну, відхиляє або просить нові варіанти.
6. **Улюблене.** Користувач позначає образ зірочкою й пізніше швидко відкриває список обраних.

## 3. Функціональні вимоги MVP
MVP складається з шести модулів. Кожна вимога має ID, критерій приймання і пріоритет: Must — без цього MVP не випускається, Should — бажано, але не блокує випуск.
Шість категорій: верхній одяг, сукні, верх, низ, взуття, аксесуари. Довідник у БД.

## 4. Алгоритм рекомендацій образів
Рекомендації в MVP працюють без нейромережі: правила відсікають поганих кандидатів, а зважена оцінка впорядковує решту. Усі ваги й таблиці лежать у конфігурації.

### Конвеєр генерації
1. **Вибір кандидатів.** З шафи беруться речі за слотами: верх, низ, сукні, верхній одяг, взуття, аксесуари. Фільтрація за стилем / опорною річчю.
2. **Поетапне збирання (beam search).** Бази (верх + низ або сукня) -> топ-30. Додається взуття -> топ-30. Верхній одяг (з/без) -> оцінка. Аксесуари (0–2).
3. **Жорсткі правила.** Відсікання невалідних комбінацій.
4. **Оцінка (Scoring).**
5. **Різноманітність.** 5 комбінацій, жодна річ не повторюється більш ніж у 2 з них.
6. **Виключення.** Хеш відсортованих ID речей для виключення показаних або відхилених.

### Жорсткі правила
* У комбінації не більше однієї речі в слотах: верх, низ, взуття, верхній одяг; аксесуарів не більше 3.
* Сукня займає верх + низ і з ними не поєднується.
* Сумісність стилів > 0 (за матрицею).
* Не більше однієї строкатої речі (з 3 кольорами).
* Не більше 3 різних акцентних кольорів серед основних кольорів речей.

### Формула оцінки
$$Score = 0.5 \cdot C + 0.3 \cdot S + 0.2 \cdot F$$

| Складова | Що вимірює | Як рахується |
| :--- | :--- | :--- |
| **C — колірна гармонія** | Чи поєднуються кольори | $C = 0.7 \cdot C_{осн} + 0.3 \cdot C_{усі}$ |
| **S — стильова єдність** | Чи речі з одного стилю | Середня попарна сумісність стилів (0–1) |
| **F — свіжість** | Чи використовуються рідко ношені речі | Середнє $1 / (1 + n)$, де $n$ — кількість збережених образів із цією річчю |

### Колірна гармонія (C)
Нейтральні: чорний, білий, сірий, бежевий, коричневий. Інші — акцентні. Різниця відтінків $\Delta h$ в HSL.

| Ситуація в комбінації | C |
| :--- | :--- |
| Лише нейтральні кольори | 0.80 |
| Один акцентний колір і нейтральні | 1.00 |
| Два акцентні, аналогові ($\Delta h \le 30^\circ$) | 0.85 |
| Два акцентні, комплементарні ($150^\circ \le \Delta h \le 210^\circ$) | 0.85 |
| Два акцентні, тріадні ($100^\circ \le \Delta h \le 140^\circ$) | 0.70 |
| Два акцентні в інших співвідношеннях | 0.30 |
| Три й більше акцентних, усі в межах $60^\circ$ | 0.40 |
| Три й більше акцентних в інших співвідношеннях | 0.10 |
| Штраф за поєднання чорного й коричневого | -0.20 |

### Сумісність стилів (S)
| | casual | sport | business | evening |

## 5. Архітектура і технологічний стек
* **Frontend:** React 18, TypeScript, Vite, React Router, TanStack Query, React Hook Form, Zod, Tailwind CSS, `@react-oauth/google`.
* **Backend:** ASP.NET Core Web API, .NET 9/10 LTS, FluentValidation, OpenAPI/Swagger.
* **ORM:** EF Core, Npgsql (PostgreSQL 16+).
* **Auth:** ASP.NET Core Identity, JWT Bearer (15 хв access, 30 днів refresh у вигляді хешу), Google Identity Services.
* **Файли:** `IFileStorage` (Docker volume на диску), `IImageProcessor` (SkiaSharp / ImageSharp).
* **Пошта:** `IEmailSender`, MailKit, Mailpit (SMTP 1025, Web UI 8025).

## 6. Модель бази даних
Таблиці:
1. `users`: `id` (uuid, PK), `email`, `display_name`, `avatar_key`, `email_confirmed_at`, `role`, `created_at`, `updated_at`.
2. `refresh_tokens`: `id` (uuid, PK), `user_id` (FK), `token_hash`, `expires_at`, `revoked_at`, `created_at`.
3. `colors` (довідник): `id` (smallint, PK), `code`, `name_uk`, `hex`, `is_neutral`, `sort_order` (14 кольорів).
4. `categories` (довідник): `id` (smallint, PK), `code`, `name_uk`, `max_per_outfit`, `sort_order` (6 категорій).
5. `items`: `id` (uuid, PK), `user_id` (FK), `name`, `category_id` (FK), `style`, `notes`, `photo_key`, `thumb_key`, `photo_cutout_key`, `created_at`, `updated_at`.
6. `item_colors`: `item_id` (uuid, PK, FK), `color_id` (smallint, PK, FK), `is_primary` (bool).
7. `outfits`: `id` (uuid, PK), `user_id` (FK), `name`, `style`, `notes`, `is_favorite`, `source`, `created_at`, `updated_at`.
8. `outfit_items`: `outfit_id` (uuid, PK, FK), `item_id` (uuid, PK, FK), `position` (smallint).

## 7. REST API (Групи ендпоінтів)
* `/api/v1/auth/*` (register, login, refresh, logout, google, confirm-email, resend-confirmation)
* `/api/v1/me/*` (profile, avatar, password, account deletion)

## 8. Нефункціональні вимоги (NFR)
* **NFR-1 – NFR-7:** Безпека, JWT 15 хв, HttpOnly Strict cookie, Global Query Filter за `user_id` (NFR-5), валідація фото за вмістом (magic bytes).
* **NFR-8 – NFR-10:** Приватність фото через авторизований ендпоінт (без прямого доступу до диску), видалення EXIF.
* **NFR-11 – NFR-15:** Продуктивність (GET /items p95 < 300ms, recommendations < 1s), відкладене завантаження, immutable cache.
* **NFR-16 – NFR-20:** Mobile-first (від 360px), оптимістичний UI, клавіатурна доступність.
* **NFR-21 – NFR-24:** Тести, 90% покриття алгоритму, CI, структуровані логи.
